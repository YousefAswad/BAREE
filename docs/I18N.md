# Languages

- **Source language:** Arabic. Every UI string is written in Arabic and used as its own translation key: `$t('الاستوديو')`.
- **English:** `resources/js/i18n/en.json` (frontend) and `lang/en.json` (backend: e-mails, notifications, server messages). English source strings used by the backend are translated to Arabic in `lang/ar.json`.
- **Direction:** `SetLocale` shares `locale` and `dir` with every page; shells and standalone pages bind `:dir`. Use logical Tailwind utilities (`me-*`, `ms-*`, `text-start`) in new code.
- **Content fields** stored as `{"ar": ..., "en": ...}` are rendered with `t()` from `@/lib/http` and fall back to Arabic.
- **Numbers and dates:** `useLocale().n()`, `money()`, `date()`.

## Workflow for new screens
1. Write the screen in Arabic.
2. Run `python3 scripts/i18n-wrap.py path/to/Page.vue` (or wrap strings by hand).
3. Run `node scripts/i18n-check.mjs` and add the missing English entries to `en.json`.
4. CI runs the check and fails on untranslated strings.

Known limits of the codemod: Arabic inside JavaScript template literals (backticks) and strings containing `{`, `}`, `|` or `@` are left for manual wrapping.
